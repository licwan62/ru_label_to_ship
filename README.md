# Ozon 标签转发货包

按 [STARTUP.md](STARTUP.md) 实现：标签 PDF → 完整发货号码 → 发货单货号 → 商品信息表尺码/材质 → 分组 PDF。保留所有原始文件，以 CSV 和 SHA-256 记录来源及人工确认。

## 安装与运行

固定批次格式以当前 `data/9.10` 为准，其他日期批次使用相同结构：

```text
data/<批次>/
  input/
    labels/        # 唯一原始标签 PDF
    发货单/         # 唯一发货单 CSV；可另存 PDF、.bak，不参与匹配
    信息表/         # 唯一商品信息 CSV
  manual_overrides.csv
  fuzzy_matches.json      # 可复用的字段别名映射
  output/
    发货包/         # 分组 PDF、逐单核对清单、分组说明
    发货包.zip      # 可选的交付压缩包，当前命令不自动压缩
  审计/             # 每次运行的时间戳目录
  发货资料/          # 已移出的资料
  历史发货包/        # 归档目录
  映射历史/          # 映射备份目录
```

运行时 `--batch` 指向批次根目录，不指向 `input`。默认不回退到旧版根目录输入位置；必要时可用单文件参数显式指定。审计和历史目录按需创建，不要求新批次预先准备。

需要 Python 3.10 或更新版本。在项目根目录执行：

```powershell
python -m pip install -e ".[test]"
python -m src.cli audit --batch data/9.10
python -m src.cli build --batch data/9.10
python -m pytest -q
```

也可使用安装后的 `ozon-ship audit --batch data/9.10`。运行依赖为 PyMuPDF 和 pypdf；pytest 仅用于测试。

默认在批次的 `input/labels/`、`input/发货单/`、`input/信息表/` 下分别寻找唯一一个 PDF、CSV、CSV。存在多个候选文件时拒绝猜测，可显式指定：

```powershell
python -m src.cli audit --batch data/9.10 --labels "data/9.10/input/labels/9.10发货.pdf" --shipment "data/9.10/input/发货单/发货商品信息9.10.csv" --products "data/9.10/input/信息表/Ozon上架链接汇总_含发货尺码及无尺码备注.csv"
python -m src.cli build --batch data/9.10 --overrides data/9.10/manual_overrides.csv --output data/9.10/output/发货包_复跑
```

`--output` 在 audit 模式指定审计目录，在 build 模式指定正式发货包目录。输出目标必须尚不存在；复跑时使用新目录，保留历史结果。

退出码：`0` 成功，`2` 存在业务或数据阻断项（审计文件仍会输出），`1` 文件、参数或生成失败。build 遇到未确认项不生成部分包。全局错误也会阻断生成，即使待确认行数为零。

## 人工确认与明确跳过

首次审计自动创建 `data/<批次>/manual_overrides.csv`，列出待处理订单，确认值留空。已有覆盖表不会被自动改写。后续新增问题可从本次待确认清单补入覆盖表。

| 字段 | 填写要求 |
| --- | --- |
| 完整发货号码 | 必填；严格作用于这一单，保留前导零和连字符 |
| 货号 | 必填；必须与该单发货单货号一致 |
| 确认发货尺码 | 发货时必填，独立尺码代码，不含说明文字 |
| 确认材质 | 发货时必填；保留业务确认的分组名称 |
| 确认人 | 必填 |
| 确认日期 | 必填，`YYYY-MM-DD` |
| 确认依据 | 必填，记录指示或依据 |
| 处理方式 | `发货` 或 `跳过`；空白/旧表缺列时视为发货 |

用户明确跳过的订单需要完整号码、货号、确认人、日期和依据；尺码、材质可以留空。它们仍在完整匹配表和跳过清单中，占原始标签页的一个明确去向，但不进入发货 PDF。跳过不豁免标签解析、号码唯一性、数量或配送服务校验。没有明确跳过依据的未匹配项仍然阻断。

该跳过功能依据本次用户对 STARTUP 的补充指示加入：`LADA-2121-LINK-S: ys; 其他跳过`。

9.10 的落实方式：

- `LADA-2121-LINK-S` 的 6 单按最新确认发 `S`，材质通过 `fuzzy_matches.json` 从 `PEVA` 统一为 `单层PEVA`。
- `VESTA-2M` 发 `M`，`0017573` 发 `XXL`，材质均已确认为 `单层PEVA`，恢复发货。
- 本次发货 55 页，无跳过、无待确认。

## 文件与匹配规则

- 仅去除字段两端空白，完整号码、货号、尾号始终为文本。CSV 不解包 `="..."`，不改变大小写、不删除前导零；除 JSON 显式配置的字段别名外，不做模糊匹配。
- 批次根目录可放置 `fuzzy_matches.json`，将已知字段别名统一为最终分组值。当前支持材质映射，按完整原值匹配；原始材质仍保留在审计表。也可用 `--fuzzy-matches` 指定其他档案。
- 读取 UTF-8（含 BOM）、GB18030、带 BOM 的 UTF-16，支持引号、逗号和字段内换行。输出统一为 UTF-8 BOM。商品和照片公式保留为源字段。
- Excel 打开 CSV 可能自动数值化标识符；请从“数据 → 从文本/CSV”导入，将完整发货号码、货号、尾四位设为文本。程序不会插入 Excel 公式来包装号码。
- 尾四位取完整发货号码**第一段的最后四位**，与 9.7 样例一致；只供查看。
- 自动尺码要求独立的字母数字代码，允许 `.`、`_`、`+`、`-`；说明文字或其他形式需人工确认标准代码。材质仅按 JSON 中显式登记的别名合并。
- 同货号信息表多行即为歧义，发货必须先消除歧义；不静默选第一行。
- 数量必须逐单为 `1`。总数恰好一致不能掩盖 `2 + 0` 等异常。
- 配送服务当前识别 `GUOO Economy Budget`、`GUOO Economy Small`；遇到其他服务阻断，需扩展识别并测试。
- PyMuPDF 解析文字；这份 PDF 用 pypdf 单独提取俄文会乱码。俄文地址、分拣标识、Ozon 号、中国地址及完整原文均保留。二维码不解码，原图保留。

## 输出与验收

每次运行均建立独立 `data/<批次>/审计/<时间戳>/`：

```text
labels_parsed.csv
shipment_normalized.csv
完整匹配表.csv
验证问题.csv
统计摘要.json
跳过清单.csv
manual_overrides.csv（本次使用的覆盖表快照）
待确认/待确认清单.csv
```

成功 build 的默认输出：

```text
data/<批次>/output/发货包/
  逐单核对清单.csv
  先看这里_分组说明.txt
  <标准材质>/发<标准尺码>码_<标准材质>_<页数>张.pdf
```

发货包按 9.7 案例只保留仓库使用的分组 PDF、核对清单和分组说明，不含待确认目录。完整匹配表、跳过清单、覆盖快照和统计摘要保存在包外的审计目录。现有 9.10 包中移出的资料保存在 `data/9.10/发货资料/`。可编辑覆盖表仍为 `data/9.10/manual_overrides.csv`。

使用 pypdf 直接复制原页，不新增封面、不缩放、不裁剪、不旋转、不栅格化。组内按原页码升序。文件名清洗同时检查 Windows 保留名称、清洗后的重名和大小写碰撞。

生成先在临时目录完成，验收成功才发布为正式目录。验收重新打开全部 PDF 和 CSV，核对号码集合、数量、分组、顺序、页面框与旋转，并用 PyMuPDF 对每个输出页和原页进行 144 DPI 像素比对，覆盖文字、二维码和图形。源 PDF、CSV、已存在覆盖表的 SHA-256 写入统计摘要，并在执行结束前再次核对。

测试包含真实 9.10 样本回归。测试需要的模拟确认只写入 pytest 临时目录，并明确标为“测试专用禁止发货”，不修改正式确认表或原始数据。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/extract_labels.py` | 逐页文字与元数据解析 |
| `src/load_sources.py` | CSV 严格读取、编码及数量标准化 |
| `src/match_records.py` | 两段精确匹配、人工确认及明确跳过 |
| `src/validate_records.py` | 号码、数量、覆盖及源文件校验 |
| `src/build_package.py` | 原页分组、核对清单及独立验收 |
| `src/cli.py` | audit/build 命令行流程 |
